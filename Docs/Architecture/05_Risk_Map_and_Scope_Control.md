# Блок 5 — Карта технических рисков и защита от Scope Creep

> Статус: **Proposed v0.1** · 2026-11-19

## 5.1 Топ-5 узких мест для соло-разработчика

### R1 · Сетевая физика: переноска, разрушения, пропы
| | |
|---|---|
| **Почему это опасно** | Самый частый убийца кооп-проектов на UE: резиновые коррекции, расхождение дыр в стенах, «прыгающие» ядра. Баги плохо воспроизводятся в одиночку и всплывают только при реальной задержке |
| **Ранние сигналы** | коррекции CMC в `p.NetShowCorrections 1` при подъёме и сбросе; разный LayoutHash; жалобы «у меня дверь открыта, у него закрыта» |
| **Архитектурный компромисс** | доктрина §3.0: state вместо симуляции; заранее заданные швы и зоны пролома; осколки — косметика без коллизии с Pawn; «виртуальные носилки» вместо физических констрейнтов; client-auth движение на время кооп-переноски; Predictive Interpolation только для свободных тел, с потолком их числа |
| **Что сохраняет AAA-ощущение** | осколки, искры и сорванные створки симулируются по-настоящему, просто у каждого свои. Игрок разницы не видит, рассинхрона геймплея нет |
| **План B** | кооп-переноска «ведущий + ведомый» (второй игрок только помогает со скоростью); переборки только через Chaos Cache |

### R2 · Производительность listen-хоста (RTX 3060, затем Steam Deck)
| | |
|---|---|
| **Почему это опасно** | Хост одновременно играет, рендерит Lumen, VSM, туман и Niagara и при этом считает сервер: ИИ, Chaos, репликацию на 3 клиента. FPS хоста — это FPS всей партии |
| **Ранние сигналы** | GT хоста > 11 мс; спайки на проломах; рост `stat net` на хосте; мерцающие теневые источники > 4 в кадре |
| **Архитектурный компромисс** | бюджеты из §3.9 с первого дня; «No Tick» (CLAUDE.md §1); Significance и Animation Budget для ИИ; навмеш только на хосте; бюджет разрушений по пресетам; Lumen Lite для Low и Deck; лимит теневых источников на комнату (проверяется валидатором) |
| **Что сохраняет AAA-ощущение** | малые замкнутые отсеки, Nanite-кит, объёмный туман и тёмная палитра. Темнота дешевле света и страшнее |
| **План B** | MegaLights (Production Ready в 5.8) вместо ручного лимита теней; DLSS/FSR; уменьшение комнат в кадре через окклюзию дверей |

### R3 · Процедурная генерация против ручного качества
| | |
|---|---|
| **Почему это опасно** | «Процедурная пресность», тупики, где Сталкер запирает отряд, швы освещения и звука между комнатами, ошибки навмеша и порталов. Уровни можно генерировать бесконечно, но доводить их вручную приходится до бесконечности тоже |
| **Ранние сигналы** | одинаковые на вид рейды после 5 seed'ов; провалы валидации > 10%; ИИ застревает на стыках |
| **Архитектурный компромисс** | **макро-процедура, микро-ручная работа**: граф из ручных комнат (15–20 на биом) плюс варианты декора, запечённые в редакторе; строгий грид и стандарт коннектора; валидатор в редакторе; Sector Preview; петли ≥ MinLoops и тупики ≤ 1 по построению; манифест реплицируется ([ADR-0003](../ADR/ADR-0003-sector-manifest-replication.md)) |
| **Что сохраняет AAA-ощущение** | каждая комната — авторская «сцена» со светом, звуком и одной сильной идеей. Разнообразие рождается из сочетаний, модификаторов аномалий и Резонанса, а не из числа ассетов |
| **План B** | наборы заранее отобранных «хороших» seed'ов на контракт (кураторские контракты) |

### R4 · Адаптивный ИИ (Эхо-Хищник) как бездонная яма
| | |
|---|---|
| **Почему это опасно** | «Адаптивный, запоминает маршруты, устраивает засады» можно полировать годами. ИИ-хоррор держится на **ощущении** интеллекта, а не на самом интеллекте |
| **Ранние сигналы** | StateTree Хищника разрастается больше 25 состояний; «умный, но не страшный»; тюнинг требует пересборки C++ |
| **Архитектурный компромисс** | Director управляет темпом и решает, когда Хищнику можно атаковать. Сам Хищник — простой StateTree. «Память» — heatmap по графу комнат и порталов, это несколько сотен float'ов, а не ML. Вентиляция — абстрактный граф. Знание о позиции идёт от Резонанса с правдоподобной неточностью: комната известна, точная точка нет. Все пороги лежат в DA |
| **Что сохраняет AAA-ощущение** | звук и телеграфирование: шаги в вентиляции, искажения от Резонанса, мерцание света перед засадой. Игрок дорисует остальное сам |
| **План B** | Хищник по скриптовым «окнам» Director'а (L4D-подход) без адаптации между рейдами |

### R5 · Scope creep контента и систем + QA мультиплеера в одиночку
| | |
|---|---|
| **Почему это опасно** | 4 класса × 3 ветки талантов, модульный крафт, мета-прогрессия корабля, дрон, лебёдка, Zero-G, 3 биома, 3 типа врагов. Каждая фича в мультиплеере стоит ×2–×3 из-за репликации и тестов на нескольких машинах |
| **Ранние сигналы** | спринт закрыт без Must; рост числа «временных» хаков; систем больше, чем закончено |
| **Архитектурный компромисс** | data-driven: новый предмет, модуль, комната или враг — это **DataAsset, а не C++**. GFP-секторы. Один класс доводится до финала раньше, чем начинается второй. Не больше одной новой системы за спринт. Секторы II–III встроены в бизнес-модель как DLC, то есть отложены по определению |
| **Что сохраняет AAA-ощущение** | глубина одного класса и одного биома важнее ширины. Срез должен продавать игру сам |
| **План B** | Early Access с Сектором I и 2 классами, остальное по дорожной карте |

## 5.2 Вторая линия рисков (watchlist)

| Риск | Решение и смягчение |
|---|---|
| Качество UE VOIP через Steam (треск, задержка) | спайк в S4; запасной вариант EOS Voice, архитектура уже backend-агностична (§3.8) |
| Отключение хоста посреди рейда (host migration в UE нет) | исход «Signal Lost»: клиенты **сохраняют взятое снаряжение**, теряют лут рейда. Сбой собственного клиента (escrow-маркер остался) считается смертью, это защищает от alt-F4 ([ADR-0005](../ADR/ADR-0005-profile-authority.md)) |
| Профиль на клиенте — значит, читерство возможно | осознанно принимаем: PvE-кооп, нет PvP и торговли. Валидация лоадаута по реестру предметов на входе в рейд |
| DLC в коопе (у одного есть, у другого нет) | контент DLC лежит в базовом депо, владение проверяется **только у хоста**, который запускает контракт. Партия не дробится |
| Переход на UE6 | заморозка на 5.8.x ([ADR-0008](../ADR/ADR-0008-engine-version-lock.md)) |
| Разношёрстные ассеты Fab | один основной кит, мастер-материалы `M_Hollow_*` с общей палитрой, пост-процесс как «клей» |
| Тестировать мультиплеер одному | второй ПК или постоянный тестер раз в неделю. С S4-06 `Build/Scripts/playthrough-mac.sh solo / coop / soak` проходит собранный билд через меню: хост и 3 клиента, два рейда, 20-минутный soak. Позже — Gauntlet/BuildGraph и Windows-версия скрипта ([ADR-0024](../ADR/ADR-0024-steam-build-signing-identity.md)) |
| Раздача Mac-билда чужим людям | сейчас подпись без песочницы и без нотаризации: свои машины открывают через «Открыть». Для плейтестеров нужны Developer ID, hardened runtime и `notarytool` — отдельная задача перед первой раздачей ([KnownIssues](../QA/KnownIssues.md)) |
| Кооп-переноска вырезана (S3-06) | E8 закрыт соло-переноской; второй несущий получает отказ без вреда. Состояние `FHollowCarryNetState` уже держит `Secondary`, поэтому кооп добавляется без смены протокола |

## 5.3 Компромиссы «AAA-эффект без лишних лет»

| Вместо… | …делаем | Экономия |
|---|---|---|
| Лицевой мокап и MetaHuman | шлемы с диегетическими визорами | месяцы анимации |
| Свободной резки мешей | заранее нарисованные швы (CutMask) | runtime-boolean и его сеть |
| Детерминированной Chaos-симуляции | state + заранее заданные зоны + косметические осколки + Chaos Cache для геройских моментов | десятки багов рассинхрона |
| Физических констрейнтов между игроками | «виртуальные носилки» + тетер в CMC | самая сложная сетевая задача проекта |
| Навмеша в вентиляции | абстрактный граф вентиляции | пересборки, третий агент навмеша |
| Пересборки навмеша для дверей | nav-link + смена area за O(1) | CPU хоста |
| ML или сложной адаптации ИИ | heatmap по графу комнат + Director | месяцы тюнинга |
| Iris, RepGraph, Mover, ресимуляции | generic-репликация + push model + dormancy + CMC | риски экспериментальных API |
| Wwise или FMOD | MetaSounds + Audio Modulation | лицензии и пайплайн |
| Огромного открытого мира | 15–20 ручных комнат на биом + процедурный граф | контент |
| Анимации TP-тиммейтов с нуля | Epic Game Animation Sample (Motion Matching) | недели |
| Тяжёлых мультиплатформенных обёрток сессий | тонкий свой `UHollowSessionSubsystem` (~400 строк, только Steam) + CommonLoadingScreen из Lyra | недели поддержки чужого кода |

**Дешёвые рычаги AAA-ощущения** (по 1 дню на «сочность» каждый спринт): звук (MetaSounds, реверб по комнатам, окклюзия), свет (Lumen, туман, мерцание), тактильность (camera shake, FOV, отдача, вибрация геймпада), материалы (раскалённый шов, сварочный валик через CPD), диегетический UI.

## 5.4 Защита от Scope Creep: правила

1. **Фильтр столпов.** Фича идёт в работу, только если усиливает хотя бы один столп:
   **(P1) физическое напряжение** (двери, сварка, проломы) · **(P2) кооп-логистика веса и риска** (ядра, эвакуация) · **(P3) адаптивный хоррор** (Хищник, Резонанс, голос). Остальное отправляется в `Later`.
2. **Kill-list для 1.0:** host migration · PvP · ranked · кросс-плей · Steam Workshop и моды · процедурные ассеты (только процедурная раскладка) · полный Zero-G-бой · больше 4 игроков · dedicated-серверы · LiveOps.
3. **Гейты:** VS (неделя 8) → *Pre-production review* (решение: идём ли в EA-скоуп) → Feature Freeze до EA → только контент и полировка.
4. **Лимит WIP:** не больше одной новой системы за спринт. Новые идеи пишутся в `Docs/Backlog.md`, а не в код.
5. **Таймбокс спайков:** неизвестная технология (голос, MegaLights, Chaos Cache) получает максимум 2 дня. Не получилось — включаем План B.
6. **Сначала данные, потом код.** Если запрос можно решить новым DA, DT или кривой, C++ не трогаем.
