# ADR-0021: Свет в бюджете — процедурный вид, аварийный свет от Резонанса, валидатор

- **Статус:** Accepted · 2026-11-20 (S4-03, план и уточнения 1–8 подтверждены владельцем проекта)
- **Связано:** [ADR-0008](ADR-0008-engine-version-lock.md) (только Lumen) · [ADR-0010](ADR-0010-editor-python-automation.md) (контент через Python) · [ADR-0020](ADR-0020-squad-resonance.md) (`MPC_Resonance`) · [Блок 3 §3.9](../Architecture/03_Physics_and_Replication_Deep_Dive.md) · [LevelMetrics §9](../QA/LevelMetrics.md)

## Контекст
- **Что было.** В каждой комнате доков стояла одна лампа без тени, в карте рейда не было ни тумана, ни экспозиции.
- **Что нужно для демо.** Героическая комната почти в финальном виде; Lumen SW; объёмный туман; строгий бюджет теневых и мерцающих источников (§3.9: не больше 4 подвижных теневых в кадре). Аварийный свет должен жить от Резонанса отряда.
- **Ограничение.** Лимит GitHub Free LFS — 1 ГБ хранилища и столько же трафика в месяц, считается каждое сохранённое бинарное состояние. Поэтому паки Megascans не подходят.

## Решение
1. **Вид без тяжёлых ассетов.** Геометрия — движковые `/Engine/BasicShapes`. Материалы — только графы узлов (уточнение 2), без своих текстур:
   - `M_Hollow_Surface`: швы панелей из мировых координат по плоскости каждой грани, потёртости из движкового шума, полосы опасности;
   - `M_Hollow_Emissive`: полосы и экраны, по желанию мерцают вместе с аварийным светом.
   - Графы собирает `create_lighting_assets.py`, хеш спецификации хранится в метаданных.
   - Состав уровня тоже хешируется: в уровне лежит маркер `HollowLightingSpec`, и уровень пересохраняется только при изменении своей спецификации.
   - Весь S4-03 занимает **0,52 МБ** бинарного контента.
2. **Героическая комната — CoreVault** (уточнение 1).
   - Корпусные материалы; рёбра стен, балки, трубы, кабели, рамка опасности и плита вокруг ядра, консоли с экранами, решётка вентиляции, светящиеся полосы у пола.
   - `LocalFogVolume` у ядра.
   - Вся отделка без коллизии и не влияет на навмеш: геймплей, сокеты, проёмы и навигация не изменились.
   - Остальные комнаты остаются в greybox-сетке, но получили световые наборы (уточнение 3).
3. **Бюджет света** (уточнение 4) — `DA_LightBudget` через `UHollowLevelMetrics::LightBudget`:

   | Тип комнаты | Ламп | С тенью | Тень + мерцание | Light function | Объёмная тень |
   |---|---|---|---|---|---|
   | Большие (Spawn, Extraction, CoreVault, Hangar, Storage) | ≤ 6 | ≤ 2 | ≤ 1 | ≤ 3 | ≤ 1 |
   | Проходные (Corridor, Junction) | ≤ 3 | 0 | 0 | ≤ 2 | 0 |

   - Худший кадр: две большие комнаты плюс проходная между ними, 2 + 2 + 0 = 4. `HollowLightBudget::WorstShadowedInView`; конфиг с худшим кадром больше 4 не проходит валидацию.
   - Лампа не светит дальше диагонали своей комнаты.
   - Мерцание выполняется light function или яркостью, свет не двигается, поэтому кеш VSM не сбрасывается.
4. **Связь с Резонансом** (уточнение 5). Аварийные лампы (без тени) используют `M_LF_Emergency`:
   - при Low — ровный тусклый красный;
   - с Medium — выпадения яркости;
   - при Critical — строб 2 Гц;
   - фаза задаётся `Time + FlickerTimeOffset` из `MPC_Resonance` и одинакова на всех машинах.
   - Полосы `MI_Strip_Emergency` мерцают так же — это «мерцание» без ламп.
   - В героической комнате вторая теневая панель с `M_LF_DyingTube` начинает «умирать» с тира High.
5. **Атмосфера** (уточнение 6) в `L_Raid_Dev`:
   - `ExponentialHeightFog` с volumetric fog на 30 м;
   - неограниченный PostProcessVolume: экспозиция по гистограмме EV100 −2…+4, local exposure, мягкий bloom, качество Lumen SW на уровне High.
   - `r.Lumen.HardwareRayTracing=0` явно: на RTX Lumen иначе сам перешёл бы на аппаратный трейсинг.
6. **Проверка бюджета** (уточнение 7) — одни и те же чистые правила (`HollowLightBudget`, HollowPCG) в трёх местах:
   - `UHollowRoomLightingValidator`: Data Validation при сохранении уровня комнаты, тип комнаты берётся из её DA;
   - автотесты;
   - runtime-команда `Hollow.Light.Dump` по собранному сектору (она печатает и туман с пост-процессом).

## Последствия
- (+) Бюджет проверяется в момент правки, а не на плейтесте. В собранном seed 7 все 14 комнат в бюджете.
- (+) Свет и материалы почти не занимают LFS. Повторный прогон скриптов ничего не пересохраняет.
- (−) **На M4 при 1080p** (ориентир, не 3060) кадр в героической комнате — 35 мс:

  | Статья | M4, мс |
  |---|---|
  | Lumen GI | 9,5 |
  | Сцена Lumen | 2,6–3,8 |
  | Прямой свет (из них lights с light function рисуются отдельно — 2,0) | 3,9 |
  | Объёмный туман | 3,5 |
  | Тени VSM | 1,5 |
  | Base pass | 0,7 |
  | Пост-процесс | 1,4 |

  - Мерцание при Critical стоит ноль.
  - По долям кадра туман, Lumen GI и прямой свет выше своих долей в §3.9, тени — заметно ниже.
  - Решение за трассой на 3060 (S4-05). Ручки: дальность и сетка тумана, качество final gather, число light function в кадре.
- (?) Не проверено, учитывает ли Lumen SW light function в отражённом свете (GI): мерцает ли там красный отсвет аварийки, видно только в окне. Прямой свет и туман мерцают точно.
- (−) Снимков под `-RenderOffScreen` нет, поэтому внешний вид проверяется вручную в редакторе.
