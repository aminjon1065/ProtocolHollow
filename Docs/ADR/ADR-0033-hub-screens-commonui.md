# ADR-0033: Экраны хаба на CommonUI — верстак, шкафчик, контракты

- **Статус:** Accepted · 2026-11-22 (S5-04, план и уточнения 1–9 подтверждены владельцем проекта)
- **Связано:**
  - [ADR-0013](ADR-0013-ui-foundation-commonui.md) — фундамент UI на CommonUI;
  - [ADR-0031](ADR-0031-hub-economy-crafting-shop-insurance.md) — экономика хаба;
  - [ADR-0032](ADR-0032-hub-skiff-terminals-upgrades.md) — хаб «Скит» и терминалы;
  - [Блок 6](../Architecture/06_Phase2_Content_and_Meta_Plan.md) (S5-04).

## Контекст
- После S5-03 терминалы открывались, но экранов не было: открытие видно только в логе, крафт, магазин, апгрейды, лоадаут и выбор контракта — только из консоли.
- Экономика — атомарные транзакции `HollowCraftingRules` на машине игрока. Хаб общий, профиль у каждого свой (ADR-0005).
- UI — CommonUI со слоями `W_PrimaryLayout`. Ввод через Enhanced Input: Enter / A, Esc / B. Деревья виджетов строят Python-скрипты.

## Решение
1. **Маршрут «терминал → экран».** `UHollowHubScreenRouter` (его держит HUD) слушает `UHollowHubTerminalSubsystem`.
   - Сервер открыл терминал этому игроку → на слое Menu появляется экран вида терминала; классы экранов заданы в `UHollowUISettings`.
   - Терминал закрыт иначе (`Hollow.Hub.Close`, другой терминал) → экран уходит.
   - Уход с экрана (Back: Esc / B, кнопка Close) закрывает его терминал.
   - Режим ввода Menu: пока экран открыт, персонаж стоит; после закрытия снова Game.
2. **База экранов `UHollowHubScreenWidget`, без Tick.**
   - Строки собираются при показе и при каждом изменении профиля (`IHollowProfileSource::ProfileChanged`).
   - Строка `W_HubRow`: имя, описание, до трёх кнопок. Виджеты строк переиспользуются, поэтому кнопка в фокусе сохраняет фокус, пока профиль меняется. Если её кнопка исчезла, фокус уходит на ближайшую (та же строка, выше, ниже), иначе на Close.
   - Внизу: строка сообщения — итог последнего нажатия или причина серой кнопки в фокусе; строка состояния — кредиты, склад, лоадаут, страховки с учётом апгрейда, «рейд идёт».
3. **Правила экранов не дублируют экономику** (`HollowHubScreenRules`, уточнение 3).
   - Каждая кнопка прогоняется через `HollowCraftingRules::Apply` на копии профиля.
   - Что правила отклонили бы, показано серым с причиной из самих правил: «Not enough credits», «Not taken into raids», «No insurance slot left», «A raid is under way…».
   - Серая кнопка остаётся фокусируемой (`SetIsInteractionEnabled(false)`): геймпад до неё доходит и видит причину; мышь видит её в подсказке.
   - Нажатие применяет ту же транзакцию, что прошла превью, с тем же id: двойное нажатие применит её один раз.
4. **`W_Workbench`** — вкладки Craft / Shop / Ship upgrades на `UCommonTabListWidgetBase` (уточнение 1).
   - Переключение: LB / RB, Q / E (новые `IA_UI_TabPrev` / `IA_UI_TabNext` в `IMC_UI`, `consume_input = false`), мышь. По краям полосы вкладок — клавиши текущего устройства.
   - Craft: «Craft» и «Craft max (N)». N — наибольшее число, которое примут правила (бисекция).
   - Shop: «BUY» — «Buy 1» и «Buy 10» (`ShopBulkCount` в конфиге); «SELL» — склад, «Sell 1» и «Sell all (+N cr)» (уточнение 2).
   - Ship upgrades: «Buy (N cr)», потом «Owned».
5. **`W_Loadout`** — склад слева («Take 1 / Take all»), лоадаут справа («Return 1» для стопок, «Return all», «Insure (N cr)»). Класс — S6-01.
6. **`W_ContractTerminal`** (уточнение 4).
   - **Хост:** «Choose» у каждого контракта (`Server_SelectContract`, сервер проверяет); выбранный выделен. «Launch the raid» — тот же путь, что «Start raid» системного меню, без подтверждения.
   - **Гость:** список без кнопок, «The host's choice», выбор хоста обновляется вживую (`OnContractChanged`), кнопки запуска нет.
   - Фокус у хоста сначала на Launch. Кнопка во всю ширину: D-pad доходит до неё с любой строки (Slate ищет соседа по перекрытию).
7. **Фокус и смена устройства.** CommonUI при переключении клавиатура ↔ геймпад заново спрашивает «желаемую цель». Ею считается кнопка, уже стоящая в фокусе, иначе первая доступная, иначе Close. Так нажатие A после стрелок действует на подсвеченную кнопку, а не на первую в списке.
8. **Профиль для тестов** — `IHollowProfileSource`: обычный C++-интерфейс в Economy. Его реализует `UHollowProfileSubsystem`; в тестах экранам подставляется профиль в памяти (уточнение 7). Настоящий профиль тесты не трогают.
9. **Вид — greybox** как у системного меню: затемнение, панель по центру, только текст. Иконки и стиль — в арт-пассе (уточнение 6).
   - Контент — `create_hub_ui_assets.py` (27-й скрипт): стили и кнопки вкладок и строк, `W_HubTabList`, `W_HubRow`, три экрана, новые клавиши в `IMC_UI`.
   - **Значения вложенных виджетов задаются на экземплярах:** стиль кнопок строки, класс кнопок вкладок. Значение, заданное тем же прогоном в class defaults вложенного WBP, до его экземпляров в другом WBP не доходит — та же ловушка, что `UseDistance` в S5-03.
10. **Экраны только в хабе** (уточнение 9): маршрут есть на любой карте, но терминалы стоят только в хабе.

**Сеть:**
- новых RPC нет;
- выбор контракта — существующий `Server_SelectContract`;
- открытие — существующий `Client_OpenTerminal`;
- всё остальное — локальный профиль.

## Проверка
- **Автотесты:**
  - `Hollow.UI.Hub.Rules` — правила на ручных условиях;
  - `Hollow.UI.Hub.{Workbench, Loadout, Contracts}` — настоящие WBP на профиле в памяти и данных проекта;
  - `Hollow.UI.Hub.Routing` — терминал → экран → Back → терминал закрыт; терминал другого игрока экран не открывает.
- **Рендер-смоук `playthrough-mac.sh screens`** (собранный Mac-билд): три экрана по очереди, геймпад (A, LB / RB, D-pad, B) и клавиатура (стрелки, Q / E, Esc); крафт, покупка, перенос, страховка, кадры каждого экрана, запуск рейда кнопкой Launch.
- **Кооп-смоук `hub --net 150`:** экраны клиента на его машине, у гостя на экране контрактов нет Launch, хост запускает рейд с геймпада.

## Последствия
- (+) **Мета-цикл в коопе без консоли:** верстак, магазин, апгрейды, лоадаут со страховкой, контракт и запуск.
- (+) Экраны не знают ни одного правила экономики: новые рецепты, предложения, апгрейды и контракты появляются строками сами.
- (−) Подписи на английском, без иконок; длинные списки только прокручиваются, без фильтров. Это арт-пасс и UX-полировка.
- (−) Реальный Enter клавиатуры не доходит до клика CommonUI в синтетических смоуках, поэтому смоук жмёт A. Живую клавиатуру и геймпад проверяют руками (`UIInputCheck`, E1).
- (?) Класс в шкафчике — S6-01; выбор сектора контрактом — S7-04.
