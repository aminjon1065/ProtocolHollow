# ADR-0043: Арт-кит без greybox — процедурные меши Blender, CC0-текстуры, склад Fab

- **Статус:** Accepted · 2026-11-23 (Art-01, план и уточнения 7–11 подтверждены владельцем проекта)
- **Связано:**
  - [ADR-0010](ADR-0010-editor-python-automation.md) — контент из скриптов;
  - [ADR-0011](ADR-0011-first-person-rendering-and-placeholders.md) — плейсхолдер Manny вне git;
  - [ADR-0021](ADR-0021-lighting-budget-procedural-look.md) — бюджет света, `M_Hollow_Surface`;
  - [ADR-0027](ADR-0027-art-prep-locks-tool-mount-montages-budget.md) — крепление инструмента, бюджет арта, ArtLock;
  - [ADR-0040](ADR-0040-cathedral-light-materials-acoustics.md) — палитра Собора;
  - арт-библия `Docs/Art/Art_Direction_Bible_v0.1.md`, `Docs/QA/ArtPassGuide.md`.

## Контекст
- После домашнего плейтеста игра выглядела «серой».
  - Семь из восьми комнат Доков носили `WorldGridMaterial`.
  - Персонажи и враги были голым Manny, инструменты — лучом из глаз.
  - Ядро было цилиндром, дверь — кубом.
- **Ограничения:** квота GitHub Free LFS (цель Art-01 — не больше 20 МБ), бюджет света и проёмов, 195+ тестов, без ручной работы в редакторе.
- Финальный арт приходит из Fab руками владельца, поэтому нужен склад, который готовит паки к бюджету.

## Решение
1. **Меши — Blender CLI** (уточнение 7).
   - `Build/Blender/hollow_kit.py` строит 23 меша из примитивов с фасками; числа — из спецификации. Состав:
     - инструменты с сокетом `Muzzle`;
     - контейнер Эфирного ядра с рунами из геометрии;
     - полотно двери с полосой сварного шва;
     - консоль, кресло, ящик и трубы хаба;
     - броня ExoFrame, Пилигрима и Хищника.
   - FBX пишется в `Intermediate/HollowArt` и в git не попадает.
   - `Build/Python/create_art_kit.py` запускает Blender (`HOLLOW_BLENDER` или `/Applications/Blender.app`), импортирует FBX старым FBX-импортёром (Interchange выключен на время импорта, его настройки явные: масштаб 100, без Nanite, без материалов из файла), назначает материалы по именам слотов и ставит spec-hash.
   - Blender нужен, только когда меняется спецификация. На Windows хватает uasset из git.
   - **Ось и единицы:** +X Blender — это +X движка, −Y Blender — это +Y движка. Метры Blender приходят сантиметрами при масштабе импорта 100. Повторный импорт берёт настройки из `AssetImportData` ассета, поэтому скрипт выставляет масштаб и там.
2. **Материалы кита** — процедурные мастера без текстур (`/Game/Hollow/Art/Materials`):
   - `M_Kit_Surface`;
   - `M_Kit_Glow` — пульс не быстрее 3 Гц, Reduced Flashes держит его ровным через `MPC_Resonance`;
   - `M_Kit_ToolGlow` — сопло ярче, пока инструмент работает (custom primitive data 0);
   - `M_Kit_Visor` — визор в цвете класса (custom primitive data 0–3);
   - `M_Kit_WeldSeam` — шов раскалён после сварки или резки и остывает сам за `CoolSeconds` по `HeatTime` = время мира;
   - `M_Kit_Hazard`, `M_Kit_Screen`;
   - 23 MI в палитре арт-библии.
   - Флаг `used_with_skeletal_mesh` обязателен: без него тела в сборке получают материал по умолчанию.
3. **CC0-текстуры** (уточнение 8).
   - Только Poly Haven, 1K, 6 наборов × 3 карты (D, N, ARM): `metal_plate`, `rusty_metal_02`, `corrugated_iron_03`, `castle_wall_slates`, `marble_01`, `plastered_stone_wall`.
   - Манифест `Build/Art/cc0_textures.json` с SHA-256. Загрузка — `Build/Scripts/fetch-cc0-textures.sh` в `Intermediate`. Импорт с `MaxTextureSize` 1024.
   - `M_Hollow_Surface` (`create_lighting_assets.py`) получил ветку `UseTextures` (static switch). Текстура проецируется на мир по главной оси нормали одной выборкой: у greybox-кубов нет пригодных UV. Швы панелей и грязь остаются поверх.
   - Без переключателя граф прежний, MI без текстур не меняются.
   - **Где включено:**
     - `MI_Hull_Wall/Floor/Ceiling` — Доки и хаб;
     - `MI_Cathedral_Stone/Floor/Vault/Pier` — словарь `PALETTE_TEXTURES` вне хеша комнат, поэтому уровни Собора не пересохранялись.
4. **Доки без greybox.** Новый `create_docks_look.py`:
   - назначает оболочкам комнат (`Floor`, `Ceiling`, `Wall_*`, `Lintel_*`) MI корпуса;
   - только материалы, без новой геометрии (уточнение 10), поэтому проёмы, бюджет света и акустика не тронуты;
   - комнаты с ArtLock не открывает;
   - уровень сохраняет, только если материал действительно сменился.
5. **Персонажи** (уточнение 9).
   - `UHollowCosmeticPartsComponent` + `UHollowCosmeticPartSet` (HollowCore) стоят на `AHollowCharacterBase`:
     - части — статические меши на костях, асинхронная загрузка (синхронная, если всё уже в памяти);
     - без коллизии и навигации, без Tick;
     - видимость как у меша-носителя (тело — `WorldSpaceRepresentation`, FP-руки — `FirstPerson` + `OnlyOwnerSee`);
     - оттенок идёт в custom primitive data.
   - Смещения считаются в скрипте из референс-позы плейсхолдера: часть задаётся в пространстве компонента и переводится в пространство кости.
   - `DA_Parts_ExoFrame` (11 частей), `DA_Parts_IronPilgrim` (6), `DA_Parts_EchoStalker` (5). Тела в материалах кита; скелет Manny, капсулы и пропорции не меняются.
   - ExoFrame следит за классом (`UHollowClassComponent`): визор шлема светится цветом класса, в руке инструмент класса — новое поле `UHollowClassDefinition::HeldTool` (у Оккультиста фонарь).
6. **Инструмент в руке.**
   - `DA_Tool_*` получили `HeldMesh`. `HeldTransform` — естественный пистолетный хват по костям пальцев: ствол вдоль пальцев, рукоять поперёк ладони.
   - Руки плейсхолдера висят по бокам, своей FP-позы у них нет, поэтому FP-инструмент держится у камеры: `bFirstPersonOnCamera`, `FirstPersonViewOffset`. Другие игроки видят его в руке тела. Луч выходит из видимого дула.
   - Свечение во время работы и искры Niagara (`NS_Tool_BeamSparks`, см. «Дополнение AK-8») — в cue луча, только пока луч во что-то попадает.
7. **Ядро, дверь, хаб.**
   - **Ядро:** визуал `BP_AetherCore` — контейнер; слот 0 (кристалл) по-прежнему получает вид предмета (очищенное ядро — золото).
   - **Дверь:** `SM_Door_Leaf` в реальном размере, с box-коллизией. Шов — слот `Seam` со своим dynamic instance (`AHollowDoor::SeamSlot/SeamWeldParameter/SeamHeatParameter`). Изменение `WeldQ` после BeginPlay греет шов: смену сварки сервер никогда не помечает «свежей», у неё своя частота отправки. Дверь, увиденная уже заваренной, холодная.
   - **Хаб:** `BP_HubTerminal` — консоль кита вместо куба. В `L_Hub_Skiff` кресло пилота, ящики, трубы и надписи CONTRACTS / WORKBENCH / LOCKER (тег `HollowArtKit`). Новых ламп нет.
8. **Склад Fab** (уточнения 11 и пункт 1 запроса).
   - `Build/Scripts/create-art-staging.sh` создаёт пустой проект UE 5.8 `~/Desktop/HollowArtStaging` вне git.
   - `run-editor-python.sh --project` запускает в нём скрипт.
   - **`Build/Python/prepare_fab_assets.py`, на складе:**
     - текстуры не больше 2048, у мелких пропов (меньше 1 м по реестру ссылок) не больше 1024;
     - мелким пропам профиль `NoCollision` по умолчанию;
     - root motion выключен;
     - отчёт веса каждого пака (`Saved/FabReport.json`).
   - **Перенос:** `HOLLOW_FAB_MIGRATE=1` переносит в `Content/Fab` только то, что держит `Build/Art/fab_manifest.json` (с зависимостями). Если `Content/Fab` после переноса превысит `budget_mb` (50 МБ), перенос не выполняется.
   - **В игре** тот же скрипт проверяет `/Game/Fab` и применяет подмены слотов из манифеста. Пустой манифест ничего не меняет.
   - **Самопроверка** `HOLLOW_FAB_SELFTEST=1`: фикстура с 4K-текстурой и мелким пропом с коллизией, затем фикстура удаляется.
   - Проект распознаётся по имени `.uproject`.
   - `Hollow.Editor.ArtBudget` теперь сканирует ещё `/HollowSector_Cathedral` и `/Game/Fab`.
9. **Инструменты:**
   - `Hollow.Art.Showcase <Class> [Forward] [Right]` — пешка без ИИ перед игроком;
   - `Hollow.Art.View <Pitch> [Yaw]`;
   - `Hollow.Art.Dump` — части персонажей и инструменты в руках.

## Последствия
- (+) Серый greybox ушёл из всех комнат, хаба и с персонажей. Новых ламп, геометрии в уровнях комнат и сетевых байтов нет.
- (+) Fab-пак подменяет любой слот без C++: меш инструмента, часть брони, текстуры MI. Склад не даёт перенести больше бюджета.
- (−) Детали брони — это силуэт на скелете Manny, а не скиннинг. Финальные персонажи придут из Fab со своим мешем (ADR-0011).
- (−) FP-инструмент у камеры не двигается с руками, пока нет FP-анимаций удержания.
- (−) `delete_all_material_expressions` удаляет примерно половину графа за вызов. Скрипты чистят граф в цикле: в `create_visor_assets.py`, `create_art_kit.py` и `create_lighting_assets.py` исправлено.
- (+) Искры и вспышка фонаря настроены в AK-8 (дополнение ниже). Систему Niagara собирает скрипт через `UHollowNiagaraAuthoring`, руками в редакторе ничего не делается.

## Дополнение · AK-8 (2026-11-23): искры резки и сварки, вспышка фонаря
1. **Сборка Niagara из скрипта.**
   - Python не умеет редактировать стек Niagara. Поэтому в HollowEditor появилась редакторная библиотека `UHollowNiagaraAuthoring` (`BlueprintCallable`, только редактор):
     - `BuildSingleEmitterSystem` — один эмиттер из движкового шаблона плюс модули в стек Particle Update;
     - `SetConstant` — значение входа модуля по концу имени (`Collision.Restitution`), должен найтись хотя бы один;
     - `SetSpriteRenderer` — материал и выравнивание по скорости;
     - `Compile` — компиляция с ожиданием, ошибка — это `false`;
     - `Describe` — эмиттеры, модули и все константы строками (на нём стоит тест).
   - Узлы модулей в графе не раскладываются: `FNiagaraStackGraphUtilities::RelayoutGraph` не экспортирован. Это только вид графа.
2. **`NS_Tool_BeamSparks`** — спецификация `SPARKS` в `create_art_kit.py` со spec-hash. Систему пересобирает тот же ассет, поэтому ссылка cue на неё не меняется.
   - Эмиттер Fountain (CPU) и модуль Collision: трассировка лучей на CPU, частица после удара живёт.
   - Числа:
     - 220 искр в секунду, жизнь 0,45–1,1 с: не больше 242 живых на инструмент (бюджет теста — 300);
     - конус 50°, 260–700 см/с;
     - гравитация −980, сопротивление 0,8;
     - до 3 отскоков, упругость 0,4, трение 0,35;
     - цвет HDR (8; 2; 0,3) — оранжевый.
   - `M_Kit_Spark` — аддитивный unlit-материал без текстур: тонкий штрих вдоль полёта (спрайт выровнен по скорости) с белым раскалённым ядром (`CoreBoost`).
   - Cue луча ставит ось +Z системы против луча (`FRotationMatrix::MakeFromZ(-Span)`): сноп летит из точки резки обратно к игроку и падает на пол.
3. **Эфирный фонарь.**
   - Свет переведён в люмены: 2500 лм. Раньше он был безразмерным (2000) рядом с практиками комнат в 3500 лм, и на снимках яркость стены не менялась вовсе.
   - Вспышка при зажигании: `AHollowLanternCue::FlashIntensityScale` ×2, затухает за `FlashSeconds` 0,3 с.
     - Работает на таймере обновления самого cue (30 Гц), без Tick.
     - Опора — яркость из умолчаний класса, поэтому вспышка не накапливается.
     - Reduced Flashes (H-1) отключает вспышку.
   - Пламя: слоты `Glow` и `Glass` меша получили `MI_Kit_LanternFlame` (`M_Kit_ToolGlow`, Idle 4 → Firing 28). Cue включает `SetFiring` у крепления, пока фонарь горит.
   - Замер по снимкам (средняя яркость стены по Y, комната Доков): 171 без фонаря → 206 на вспышке → 194 при ровном свете.
4. **Проверка.**
   - Новые тесты: `Hollow.Editor.ArtSparks` (один CPU-эмиттер, гравитация, Collision без убийства, 1–4 отскока, бюджет живых искр, скорость ниже предела решателя, материал и выравнивание спрайта) и `Hollow.Game.Art.LanternFlash` (вспышка, затухание по таймеру, без вспышки при Reduced Flashes, пламя по `SetFiring`).
   - `Hollow.Art.Dump` печатает свет фонаря: место, направление, яркость.
   - Strict 206/206. Сборки редактора и игры (Development, Shipping): 0 предупреждений проекта.
   - На пакете после `--clean`: все 16 режимов `playthrough` прошли; soak PASS 81,6 FPS.
   - Повтор soak с другим seed дал P95 18,1 мс: две минуты у ядра, сварки в это время не было (KnownIssues, прогоны AK-8).
   - E9 со сваркой: Low 54,6 / 55,5, High 22,3 / 24,1 FPS (Mac M4), то есть от −0,7 до −5,1 % к Art-01, в пределах порога 10 %.
   - Искры отдельно: без спрайтов и коллизий Niagara FPS расходится на ±1, в пределах разброса прогонов.
   - По дороге найдено (KnownIssues AK-13): замеры E9 с 2026-11-22 шли без сварки, скрипт стирал профили не там. Исправлено, подробно — [PerfE9](../QA/PerfE9.md).
