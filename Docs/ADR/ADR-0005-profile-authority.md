# ADR-0005: Авторитет профиля — профиль у клиента, авторитет рейда у хоста

- **Статус:** Accepted · 2026-11-19 (Proposed → Accepted: подтверждено владельцем проекта, Q1–Q6)
- **Связано:** CLAUDE.md §3 (Strict Server Authority: crafting, extraction rewards) · [Блок 2 §2.5, §2.9](../Architecture/02_Folder_Structure_and_Class_Hierarchy.md)

## Контекст
P2P listen-сервер без бэкенда (премиум без LiveOps). Мета-прогрессия каждого игрока (кредиты, склад, чертежи, уровни, апгрейды челнока) хранится на **его** машине (SaveGame + Steam Cloud). Хост не может авторитетно проверить чужой профиль, потому что его у хоста просто нет.

## Решение
1. **Внутри рейда** авторитет у хоста, строго по CLAUDE.md §3: подбор, урон, инвентарь, перемещения предметов, полевой крафт, итог эвакуации.
2. **Вход в рейд:** клиент отправляет `Server_SubmitLoadout(FHollowLoadoutSnapshot)`. Хост проверяет снимок по реестру определений и лимитам стаков и отклоняет невалидное. *Реализовано в S5-01 ([ADR-0030](ADR-0030-raid-inventory-loadout.md)): по запросу хоста уже в рейде, проверка мягкая — невалидные слоты отбрасываются.*
3. **Выход:** хост вычисляет `FHollowRaidResult` и отправляет клиенту. Клиент применяет `FHollowProfileDelta` через `FHollowExtractionResolver` к **своему** профилю.
4. **Крафт и торговля в хабе** — транзакции `UHollowProfileSubsystem` над локальным профилем с валидацией по `UHollowRecipeDefinition`. «Сервер» для профиля — сам владелец профиля.
5. **Escrow:** перед рейдом в SaveGame пишется маркер со снимком лоадаута.
   - Отключился **хост** → исход «Signal Lost»: взятое снаряжение сохраняется, лут рейда теряется.
   - **Собственный** вылет или alt-F4 (маркер нашёлся при следующем запуске) → исход по правилам смерти (остаётся только застрахованное).
6. Чит-устойчивость профиля осознанно не обеспечиваем: PvE, нет PvP, нет торговли между игроками.

## Последствия
- (+) Нет бэкенда и его затрат; оффлайн-соло работает; Steam Cloud бесплатен.
- (−) Профиль можно отредактировать вручную. Для PvE-кооп приемлемо.
- Подтверждено (Q2); CLAUDE.md §3 обновлён.
