# ADR-0017: Железный Пилигрим — мозг на StateTree, пролом по nav-link, урон через execution

- **Статус:** Accepted · 2026-11-20 (S3-04, план и уточнения 1–7 подтверждены владельцем проекта)
- **Связано:** CLAUDE.md §3, §4, §5, §6 · [ADR-0004](ADR-0004-runtime-navmesh-door-links.md) (двери на nav-link) · [ADR-0014](ADR-0014-breachable-bulkheads.md) (`IHollowStructural`) · [ADR-0016](ADR-0016-raid-flow-extraction-escrow.md) (смерть игрока) · [Блок 2 §2.4, §2.7](../Architecture/02_Folder_Structure_and_Class_Hierarchy.md) · [Блок 3 §3.3, §3.7](../Architecture/03_Physics_and_Replication_Deep_Dive.md)

## Контекст
Первый враг вертикального среза. Пилигрим слышит и видит игроков, преследует их, ломает заваренные двери и бьёт. Урон должен проходить через GE, решения — приниматься StateTree. Модуль `HollowAI` зависит только от Core и GAS (ADR-0001), поэтому дверь и переборку он видит только через интерфейсы Core. До S3-04 дверь не умела ломаться: строки 7–8 таблицы §3.3 не были реализованы.

## Решение
1. **Состав.**
   - `AHollowEnemyCharacter` (AI): собственный ASC в режиме Minimal и `UHollowHealthSet`; всё остальное — из `UHollowEnemyDefinition` (primary asset `HollowEnemy`).
   - Пилигрим — это `BP_IronPilgrim` с данными, нативного наследника нет.
   - Капсула 80/140 совпадает с nav-агентом Heavy; фильтр путей `NAV_Filter_Heavy` берётся из определения.
2. **Мозг.**
   - `AHollowAIController` хранит факты и выполняет «активности» (`EHollowAIActivity`: Patrol, Chase, Investigate, Attack, Breach) на таймерах и колбэках движения и способностей, без Tick.
   - Факты: цель в поле зрения, последний стимул, препятствие на пути.
   - `ST_IronPilgrim` (схема StateTree AI component) только выбирает активность. Порядок детей корня: Breach → Attack → Chase → Investigate → Patrol, у каждого свои enter-условия.
   - Переход на корень срабатывает при завершении активности и по событию `Hollow.AI.Event.Reconsider`, которое контроллер шлёт при смене фактов. Задачи не тикают, и дерево спит между событиями.
   - Цель, потерянная из виду, остаётся целью `TargetMemorySeconds`. Мерцание прямой видимости у края проёма иначе дёргает дерево каждые 0,3 с (найдено в двухпроцессном смоуке).
3. **Препятствие на пути.**
   - `UHollowPathFollowingComponent::StartUsingCustomLink`: если владелец связи — `IHollowStructural` и его `GetPassage()` не `Clear`, контроллер останавливается на следующем тике и шлёт Reconsider. Состояние Breach выигрывает.
   - Новое в `IHollowStructural`: `EHollowPassage {Clear, Open, Breach}`:
     - дверь `Closed` без замка — `Open` (её открывают как игрок, уточнение 1);
     - `Welded`, `Locked`, `Barricaded` и целая переборка — `Breach`;
     - открывающаяся створка — `Open` (подождать).
   - После пролома путь запрашивается заново и идёт через ту же связь, теперь `Doorway`. `WatchPath` из Physics ИИ не нужен.
4. **Пролом двери (§3.3, строки 7–8).**
   - Структурный удар сначала тратит шов (`Weld × WeldAbsorbFactor`), остаток идёт в `Structure`.
   - Состояние двери не меняется (вмятый шов — всё ещё шов), пока при `Structure = 0` дверь не станет `Breached`. Это конечное состояние.
   - `StructureQ` теперь реален. Удар сразу рассылается как `StructureChanged`; направление удара — новый флаг `BreachedBackwards` в байте флагов.
   - Во всех состояниях `Breached` створка скрыта и без коллизии.
   - Свежий пролом бросает локальную косметическую копию створки вдоль удара, по бюджету `UHollowDestructionBudgetSubsystem`, на канале HollowDebris.
   - `DA_Door_Standard`: шов 600, структура 300. Полностью заваренную дверь Пилигрим ломает за 8 ударов (≈ 18 с).
5. **Атаки** — `UHollowGA_EnemyAttack`:
   - ServerOnly, InstancedPerActor, запуск по gameplay event `Hollow.Event.Enemy.*`, цель в payload;
   - стоп и фокус на цель → кьюшка `GameplayCue.Hollow.Enemy.Windup` (реплицируется в Minimal) → удар в конце замаха → восстановление; всё на `UAbilityTask_WaitDelay`, тайминги из `UHollowEnemyAttackDefinition`;
   - `UHollowGA_PilgrimBreach`: `IHollowStructural::ApplyStructuralDamage` в пределах досягаемости;
   - `UHollowGA_PilgrimMelee`: sphere sweep перед собой, только живые игроки в прямой видимости, урон спеком `GE_Damage_Kinetic`. Кто ушёл за время замаха, не получает удара.
   - Montage и MotionWarping ждут арт (уточнение 2); отбрасывания нет (уточнение 5).
6. **Урон.**
   - `UHollowDamageExecution` (GAS):
     - база — SetByCaller `Hollow.Data.Damage`, тип — `UHollowDamageEffect::DamageType`;
     - броня цели захватывается при выполнении;
     - `damage × K / (K + Armor)` для типов, где броня действует; иммунитет по тегу типа;
     - правила лежат в `UHollowDamageSettings` (DefaultGame.ini).
   - Результат пишется в `IncomingDamage`, дальше работает `UHollowHealthSet`, а смерть игрока — по ADR-0016.
   - `GE_Damage_Generic` остаётся отладочным «чистым уроном» мимо брони.
7. **Перцепция.**
   - Sight и Hearing на контроллере, параметры из определения.
   - Команд пока нет, а штатный решатель отношений считает одинаковые `NoTeam` друзьями. Поэтому включены все аффилиации, а `IsCandidate` оставляет только живых игроков.
   - Слух в S3-04 питает только `Hollow.AI.Noise`; настоящие шумы — в S3-05.
8. **Без EQS в S3-04** (уточнение 3, отступление от CLAUDE.md §6 одобрено): точка патруля — случайная достижимая точка Heavy-навмеша вокруг «дома». EQS придёт с Хищником в S4-01.
9. **Спавн.**
   - `FHollowSocketActorRule` получает `MaxPerSector` и `Pick`; правила применяются по порядку.
   - Правило `EnemySpawn → BP_IronPilgrim` (1, `FarthestFromSpawn`) стоит перед правилом маркеров, так что сектор получает ровно одного Пилигрима в самом далёком по графу комнат сокете. Выбор детерминирован по манифесту.
   - Мозг стартует при possess (уточнение 7).
10. **Навигация.** `DefaultQueryExtent` агентов расширен до X/Y 150 (Heavy) и 100 (Standard). Иначе враг, остановившийся посреди проёма (вырез 40 + радиус агента), не находил навмеш и не мог уйти.
11. **Сборка контента.** `UHollowStateTreeAuthoring` (HollowEditor) собирает и компилирует дерево по JSON-спеке из `create_pilgrim_assets.py` и описывает его обратно, чтобы скрипт был идемпотентным.

## Последствия
- (+) Пролом идёт через ту же связь, что и обход, без пересборки тайлов. Сеть видит только состояние двери: `Welded` → удары → `Breached` (fresh), а створка у каждой машины своя.
- (+) Решения проверяются тестами без сети (`Hollow.Game.Pilgrim.*`). Новые враги — новое определение и дерево без нового C++.
- (−) Пока факты меняются редко, контроллер ничего не делает. Но каждая перепланировка — новый путь, поэтому смены фактов нужно держать редкими: память цели, порог нового шума.
- (−) Смерть игрока даёт 2–3 коррекции движения с нулевым смещением (сервер выключает движение). Это поведение ADR-0016, к Пилигриму отношения не имеет.
- (?) Анимации, MotionWarping, отбрасывание, урон по Пилигриму от игроков и EQS — следующие задачи.
