# ADR-0009: Кроссплатформенный тулчейн — разработка на macOS, сборка и тесты Win64 на Windows

- **Статус:** Accepted · 2026-11-19 (задано владельцем проекта)
- **Связано:** CLAUDE.md §2 (Strictly cross-platform C++), §7 (DoD) · ADR-0008

## Контекст
- **Основная разработка:** macOS на Apple Silicon (M4, 16 ГБ unified memory), Xcode 27.2 / Apple Clang 21. Движок UE 5.8.4 из Epic Launcher. Xcode 27.2 входит в диапазон, который UE 5.8 допускает: 15.2–27.9 (`Engine/Config/Apple/Apple_SDK.json`).
- **Win64 и живые тесты:** домашний Windows-ноутбук (8 ГБ VRAM, 16 ГБ RAM). На нём собирается и пакуется Win64-билд и проходят кооп- и FPS-тесты. Кросс-компиляции Win64 с macOS в UE нет.
- Продукт — **только Win64** (Steam; Steam Deck через Proton). Mac — платформа редактора, а не таргет.

## Решение
1. **Один и тот же C++ обязан собираться без warnings в Apple Clang и в MSVC.** Правила кода — в CLAUDE.md §2 «Strictly cross-platform C++». В коротком виде: без платформенных заголовков и `#if PLATFORM_*` в геймплее, без расширений компиляторов, только типы фиксированного размера (никакого `long`), `TEXT()`/`FString`, include-пути в точном регистре, LF, сборка проходит и без unity.
2. **MSVC на Windows:** Visual Studio 2022 с MSVC **14.44.35211+** или **14.50.35723+**, Windows SDK **10.0.22621**. Версии 14.39–14.43, 14.44.0–14.44.35210 и 14.50.0–14.50.35722 UE 5.8 банит (`Engine/Config/Windows/Windows_SDK.json`).
3. **Плагины:** включены только поддерживающие и `Mac`, и `Win64`; Windows-only и Mac-only запрещены. Будущий апскейлер (DLSS и т.п.) — отдельный ADR, `PlatformAllowList: [Win64]`, без C++-зависимостей.
4. **Шейдеры:**
   - Win64 — только **DX12 / SM6**: SM5 убран из D3D12, D3D11 отключён. Это вдвое сокращает компиляцию шейдеров и память кука.
   - Mac-редактор — только **Metal SM6**, как в шаблоне UE 5.8.
   - Статическое освещение выключено (`r.AllowStaticLighting=False`), потому что процедурные уровни всё равно не запечь. Это ещё и меньше пермутаций.
5. **Сборочные скрипты** (`Build/Scripts/`):
   - `build-editor-mac.sh`: Mac-редактор, флаг `--no-unity`, **гейт нулевых warnings** по исходникам `Source/Hollow*`.
   - `run-tests-mac.sh` / `run-tests-win64.ps1` (+ `.cmd`): сборка редактора с гейтом warnings → headless-автотесты `Hollow.*` → отчёт; ненулевой код выхода при любом сбое (одинаковые коды на обеих ОС).
   - Общая логика Windows-скриптов (поиск движка, лимиты по RAM, гейт warnings) живёт в `HollowBuild.psm1`.
   - `package-win64.ps1` / `.cmd`: BuildCookRun под 16 ГБ RAM. UBT `-MaxParallelActions` берётся из RAM (≈2.5 ГБ на действие, 4 при 16 ГБ). Число ShaderCompileWorker тоже из RAM (≈1.25 ГБ на воркер, 6 при 16 ГБ, через `[DevOptions.Shaders]`). GC кукера срабатывает при < 3 ГБ свободной памяти. По умолчанию кук инкрементальный (`-iterate`). Есть проверки диска и page file, тот же гейт warnings для MSVC.
6. **Синхронизация двух машин:** Git + LFS (бинарные ассеты, исходники арта и звук). DDC у каждой машины свой, общий DDC не настраиваем. Remote-хостинг LFS выбирается отдельно.
7. **Бюджет VRAM считаем от 8 ГБ** (ноутбук строже, чем 12 ГБ у RTX 3060). FPS-цели CLAUDE.md §5 по-прежнему заданы для RTX 3060. Замеры на ноутбуке — прокси: питание от сети, план «Высокая производительность», модель GPU записывается в отчёт.
8. **PIE на Mac с 16 ГБ unified memory:** клиенты в одном процессе, маленькие окна, Scalability редактора Medium. Steam-тесты на двух машинах — через упакованный Win64-билд и Mac Development-билд из редактора (или второй Windows-ПК).

## Последствия
- (+) Код с первого дня остаётся переносимым. Ошибки, которые видит только MSVC или только Clang, ловятся гейтом warnings на обеих машинах.
- (+) Пакетная сборка укладывается в 16 ГБ без свопа в типичных условиях.
- (−) Без SM5 и DX11 игра не запустится на GPU без DX12 SM6 (до GTX 10xx / RX 400). Для таргета RTX 3060+ это приемлемо.
- (−) Ограничения параллелизма замедляют чистую сборку. Инкрементальный кук это компенсирует.
