# ADR-0011: Первое лицо через штатный First Person Rendering и политика плейсхолдер-контента

- **Статус:** Accepted · 2026-11-19 (S1-04, подтверждено владельцем проекта)
- **Связано:** ADR-0009, ADR-0010 · [Блок 2 §2.3](../Architecture/02_Folder_Structure_and_Class_Hierarchy.md)

## Контекст
- Кооп-хоррор от первого лица в тесных отсеках. Классическая проблема: FP-руки проходят сквозь стены, а тиммейты должны видеть полноценное TP-тело.
- В UE 5.8 есть штатный First Person Rendering: `EFirstPersonPrimitiveType` на примитивах, `bEnableFirstPersonFieldOfView` и `bEnableFirstPersonScale` на камере. Его использует официальный шаблон FirstPerson 5.8.
- Финального арта ExoFrame пока нет. Квота GitHub Free LFS небольшая, а плейсхолдеры (UE5 Manny и анимации шаблонов) весят около 90 МБ.

## Решение
1. **`AHollowExoFrameCharacter`:**
   - TP-тело (`GetMesh()`) имеет тип `WorldSpaceRepresentation`: его видят остальные игроки, владелец видит только тень.
   - `FirstPersonMesh` имеет тип `FirstPerson` и `OnlyOwnerSee`, позу копирует из TP через `ABP_FP_Copy`.
   - Камера закреплена на сокете `head` FP-меша, у неё свой FOV и масштаб для первого лица.
   - Все числа (смещения, FOV, масштаб, капсула) — данные `BP_ExoFrame`, не C++.
2. **Плейсхолдеры** копируются из локальной установки UE 5.8 скриптами `Build/Scripts/import-placeholders.sh` / `.ps1`.
   - Пути сохраняются как в шаблоне: `/Game/Characters/Mannequins`, `/Game/FirstPerson/Anims`. Так внутренние ссылки остаются валидными.
   - Копируется набор, замкнутый по ссылкам: без Quinn-материалов и анимаций атак.
   - Папки в `.gitignore`, **в git не попадают**.
   - `package-win64.ps1` импортирует их сам, если их нет.
3. **Контент персонажа** (IA, IMC, InputConfig, MovementTuning, `BP_ExoFrame`, `BP_GameMode_Hub`) создаёт идемпотентный `Build/Python/create_exoframe_assets.py` (ADR-0010). Он создаёт только отсутствующие ассеты, поэтому тюнинг из редактора не перезаписывается, и затем валидирует всё прочитанное с диска.
4. Финальный арт ExoFrame появится под `/Game/Hollow/Characters/` и пойдёт в LFS. Тогда ссылки `BP_ExoFrame` переключаются на него, а плейсхолдеры удаляются.

## Последствия
- (+) Руки не проходят сквозь геометрию, тень владельца корректна с VSM, а TP-тело видят тиммейты.
- (+) Плейсхолдеры не расходуют квоту LFS.
- (−) На каждой машине после клона нужен один шаг: `import-placeholders`.
- (−) В шаблонных ассетах есть висячие ссылки (`CR_Mannequin_Body` → `/Game/Developers/...`, `MM_WallJump`). Так же и в штатном шаблоне, на работу это не влияет.
